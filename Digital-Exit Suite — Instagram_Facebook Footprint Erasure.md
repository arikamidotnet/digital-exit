# Digital-Exit Suite — Instagram/Facebook Footprint Erasure


## Problem Statement

Build a repeatable, mostly-automated suite that archives everything worth keeping off an Instagram account (posts, archived stories, saved-post media, followers/following), renders the follower set into a searchable "contacts database" categorized as Company/Influencer/Friend/Media, then deletes the accounts — all documented so it can be recreated as a program or an agent task, and later reused for family and friends.

## Requirements (locked via interview)

* Instagram: full archive + delete. Facebook: wipe only, no export. WhatsApp: deletion tips only, no export.
* Contacts DB scope: Instagram followers AND following (Instagram only).
* Saved posts: download the actual media file for every save; retry unavailable ones a few times before giving up.
* Follower categories: Company (business link/bio), Influencer (high follower count / creator bio), Media (news/outlet handle), everything else Friend. Requires reading each follower's profile.
* Form factor: Go CLI that emits a folder containing a static TypeScript webpage (offline, client-side searchable). Runs on Nix (Linux/fish).
* Scale: 1k–20k followers/following → medium.
* Automation: as programmatic as possible; authenticated wrapped-browser login acceptable; manual only where unavoidable. Delete only after archive is verified.

## Key Facts from Research

* Official export path: Accounts Center → Your information and permissions → Download your information → Create export → Instagram → Export to device (JSON, all-time, high quality). Link expires in 4 days; preparation can take hours to 30 days.
* Archive layout (`instagram-user-DATE/`): `media/{posts,stories,archived_posts,reels}/YYYYMM/`, `connections/followers_and_following/{followers_*.json, following.json}`, `your_instagram_activity/saved/{saved_posts.json, saved_collections.json}`, `.../likes/liked_posts.json`, `.../comments/`, `.../messages/inbox/{conversation}/`.
* The export gives follower *usernames only* and saved posts as a link list with empty media fields. Real saved-post media and follower bios must be fetched separately while the account is still alive — this is Stage 2, the time-consuming/risky part.
* yoinks/yt-dlp download media by URL; they are not list exporters. Saved-posts export = official export (list) + yt-dlp/yoinks (media per permalink).
* Instagram deletion: Accounts Center → Personal details → Account ownership and control → Deactivation or deletion → Delete account. 30-day grace period (login cancels it); ~90 days for full purge. Deleting Instagram also deletes the linked Threads.

## Tech Stack

* Nix flake (`flake.nix`) providing Go, Node/pnpm, yt-dlp, ffmpeg, and a Playwright Chromium binary — reproducible environment matching the user's Nix/Linux setup.
* Go CLI: orchestrates stages, parses export JSON, maintains a local SQLite DB, classifies followers, invokes yt-dlp for media, verifies integrity.
* Viewer: emitted by the Go binary (`cli/viewer.go`) as one self-contained HTML file — dataset embedded as base64, vanilla JS for search/filter/tabs. Chosen over a Vite/TypeScript project because it needs no build step, no npm install, and no network at read time; the artifact cannot rot when the toolchain does. Offline-openable straight from disk, which was the actual requirement.

## Directory Scaffold (`digital-exit/`)

* `01-request/` — export request log + captured download links per account.
* `02-archive/` — unzipped official archives, one subdir per account.
* `03-media/` — downloaded media: posts, stories, saved posts (subdirs), plus an `unavailable.log` for saves that failed after retries.
* `04-processed/` — normalized JSON records + local SQLite DB (`contacts.db`).
* `05-output/index.html` — final deliverable: the self-contained viewer, opened directly in a browser.
* `nix/` — flake and shell.nix.
* `cli/` — Go program (main.go, parse.go, classify.go, media.go, verify.go).
* `runbook.md` — step-by-step recreation guide + agent-task spec.
* `README.md` — quickstart and layout overview.

No `web/` directory: the viewer is generated by `cli/viewer.go`, so there is no separate frontend project to build. SQLite (`contacts.db`) stays reserved — `04-processed/data.json` is the store of record.

## Instagram JSON Export Structure & Normalization

The Stage 3 parser is built around the real Meta archive layout rather than an abstract schema, and maps each known folder to normalized records:
* media/{posts,stories,archived_posts,reels}/YYYYMM/ plus your_instagram_activity/media/*.html -> posts and stories (caption, timestamp, geotag, tagged users).
* connections/followers_and_following/{followers_*.json, following.json} -> follower and following username lists.
* your_instagram_activity/saved/saved_posts.json + saved_collections.json -> saved-post link list (media field is empty; posts vs reels inferred from /p/ vs /reel/).
* your_instagram_activity/likes/liked_posts.json, comments/, messages/inbox/{conversation}/ -> likes, comments, DMs.

Quirks the parser must tolerate (observed across exports): saved_posts labels are localized per export language (e.g. 网址 for URL) and non-ASCII text is often double-encoded (UTF-8 bytes read back as Latin-1), so captions need re-decoding; folder names shift between archive versions, so paths are discovered by scanning rather than hard-coded; the flat saved list is the superset over collections. The parser reports gaps during verification instead of failing silently.

## Pipeline Stages

Stage 0 — Nix environment and scaffold.
Stage 1 — Request & download the official Instagram export (manual); drop the resulting ZIP into 01-request/.
Stage 2 Ingest — `digital-exit ingest <path>` accepts a raw .zip, .tar.gz, or an already-unzipped directory; stages it into 02-archive/, locates the export root by signature rather than path, and normalizes every known folder into `04-processed/data.json`. Drop-it-in-whatever-format: no fixed path or schema required.
Stage 3 Enrich — `digital-exit run` yt-dlps each saved permalink into 03-media/saved/ with 3 retries then an `unavailable.log` entry (never aborts). With `--auth`, contacts still missing a bio or follower count are resolved through the Instagram Graph API using a token in `01-request/auth.json`. Implemented as an API-token path rather than a Playwright browser session: less fragile, no login automation to maintain. Must complete before any deletion.
Stage 4 — Enrichment is merged into the normalized records in place (data.json is rewritten idempotently; already-fetched work is skipped).
Stage 5 — Classifier assigns Company/Influencer/Media/Friend via bio-vocabulary, follower-count, and external-link heuristics across followers AND following.
Stage 6 — Emit `05-output/index.html`, the self-contained offline viewer.
Stage 7 — Verify: archive presence, data.json round-trip integrity, counts with category breakdown, and on-disk confirmation of every downloaded save. Deletion is gated on this passing.
Stage 8 — Delete Instagram (manual); runbook covers the Facebook wipe and WhatsApp tips.

## Classification Logic

For each follower/following profile read in Stage 2: if bio or website indicates a business/brand → Company; if follower count is high and bio reads as creator/partner/content → Influencer; if handle/bio matches a news outlet/media → Media; otherwise Friend. First match wins, with Friend as the fallback bucket.

## Risks & Mitigations

* Account throttling/bans during Stage 2: persistent logged-in session, human-like throttling, resumable downloads, and `--latest-stamps`/done-tracking so retries don't re-fetch. Stage 2 runs before deletion so a slow run is safe.
* Saved posts pointing to deleted/private content: retry a few times, then record in unavailable.log; do not abort the run.
* Export incompleteness (region/format drift): parser tolerates multiple known archive layouts and reports gaps during verification rather than failing silently.
* 4-day download window: Stage 1 logs the link immediately and downloads promptly.

## Orchestration

Not applicable. This is an iterative single-developer build; no parallel child agents are required.
